# Migrating to v0.3.0 — audit logging

One feature: every tool call now leaves a record. Written during the work, so
the traps below are the ones actually hit rather than ones inferred from the
diff afterwards.

## Order to apply

1. `cli_mcp/audit.py` — new file, no dependencies on the rest of the package.
   Copies across unchanged.
2. `cli_mcp/cli_executor.py` — rename `_build_argv` → `build_argv` and update
   its two call sites. Nothing else in this file changes.
3. `cli_mcp/server.py` — the wiring. Largest hunk; see the traps below.
4. `tests/conftest.py`, `tests/test_audit.py`, `tests/test_audit_wiring.py`,
   `tests/test_e2e_transport.py` — test bodies copy across unchanged.
5. `configs/example.yaml` — **re-derive**, do not port verbatim. See
   "Config" below for the keys and their defaults.
6. `scripts/verify/conformance.py` — five new probes under a `0.3.0` heading.

Steps 1–2 are independently green. Step 3 is where the suite would fail if
you stopped halfway.

## Config

New optional `audit:` block. **Absent means enabled with defaults**, so an
existing config keeps working with no edit — but it will start writing to
stderr, which is the one thing to check before rolling out (see "Operational"
below).

| Key | Default | Notes |
|---|---|---|
| `enabled` | `true` | |
| `destination` | `"stderr"` | Or an absolute path. Relative paths are rejected at parse time. |
| `max_command_bytes` | `4096` | Commands longer than this are truncated and marked. |
| `on_write_failure` | `"continue"` | Or `"deny"`. See below. |

## Traps

### The principal ContextVar must be set in `handle_sse`, not `handle_messages`

This is the one worth the migration note on its own.

A tool call does **not** execute in the task of the POST request that carried
it. `handle_messages` hands the message to the session's stream; the handler
runs in the task group inside `mcp_server.run()`, which is spawned from
`handle_sse`. anyio tasks inherit context at spawn time, so:

- a `ContextVar` set in `handle_sse` **is** visible in `call_tool`
- a `ContextVar` set in `handle_messages` **is not** — it reads as unset

Verified against the real transport before the field list was chosen. The
consequence is baked into the design: attribution is connection-scoped, and
per-request facts (the POST's own `User-Agent`, for instance) are not
reachable without patching the transport.

If your fork has moved to streamable HTTP, **re-verify this** before porting
step 3 — the task topology is the thing that makes it true, and it is not the
same transport. `tests/test_e2e_transport.py::test_audit_principal_over_transport`
is the test that pins it; adapt it to your transport rather than dropping it.

### `deny` posture must gate execution, not just logging

`on_write_failure: "deny"` raises `AuditWriteError` from the *decision* write,
which `call_tool` converts into a refusal before anything is spawned. The
*outcome* write is different: by then the subprocess has already run, so a
failure there is counted rather than raised. Converting a real result into a
refusal at that point would report a falsehood to the caller.

If you port the try/except around the decision write but not the one around
the outcome write, a fail-closed deployment will start reporting successful
calls as errors.

### Every exit from `call_tool` needs a record

`call_tool` has eight exits — seven refusals plus the execute path. The
failure mode is porting six of them. `tests/test_audit_wiring.py` parametrizes
all seven refusals and asserts an exact record count, and
`test_every_refusal_path_is_covered` fails if the parametrization drifts from
the source. Port both.

### `AUDIT` is a lazily-built global keyed off `CONFIG`

Same pattern as `REGISTRY`. Test fixtures that swap `CONFIG` must reset
`AUDIT` too, or a test writes into a previous test's torn-down `tmp_path` —
order-dependent and silent. `conftest.py` gains an autouse fixture for this;
if your fork has its own fixture set, replicate it there.

## What to check in your own catalog

- **Nothing in the catalog schema changed.** No entry needs editing.
- The `startup` record now writes your allow/deny patterns verbatim into the
  log. If any catalog entry embeds something you would not want in a log
  aggregator, that is now worth knowing. Patterns are matched against command
  strings, so this is unusual — but check before rolling out.

## Operational

- **The default destination is stderr.** Under systemd that lands in journald
  with the rest of the service output. If anything downstream parses this
  service's stderr, it will start seeing JSON lines it did not see before —
  this is the `[behavior-change]` part. Set `destination` to a file if that
  matters.
- A file destination is **opened per record** rather than held open, so
  rotation by rename works with no SIGHUP handler and there is no descriptor
  to go stale.
- Writes are **synchronous**. At this call volume that is the right trade, but
  a hung filesystem stalls the event loop for every in-flight call, not only
  the one being logged. Prefer a local path over a network mount.

## What this does not give you

Stated here because it is easier to absorb now than to discover during an
incident review:

- Connections are unauthenticated, so `principal.authenticated` is always
  `false`. The log establishes what the server did, not who asked it to.
- With `on_write_failure: "continue"`, anyone who can fill the destination
  disk can make the log lossy. Drops are counted and surface as
  `audit_dropped` on the next record that lands, so the loss is visible after
  the fact — but this is not a tamper-evident trail.

## Unrelated defect noticed during this work, not fixed

`parse_pipeline("")` raises `pipeline grammar: empty segment`, so the 0.2.0
fix that let `check_command` accept an empty command is unreachable through
`server.call_tool`. A tool with `allow: ["*"]` still cannot be invoked bare —
`uptime`, `free`, `dmesg`. `tests/test_filter.py` covers `check_command`
directly, which is why the gap survived. Left alone to keep this release
single-purpose; if your fork depends on argument-less invocation, it is
already broken there too.
