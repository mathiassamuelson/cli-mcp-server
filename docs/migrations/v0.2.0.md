# Migrating to v0.2.0

From `v0.1.0`. Read [DOWNSTREAM.md](../DOWNSTREAM.md) first if you have not.

**Before porting anything**, run the probes against your fork:

```bash
python scripts/verify/conformance.py --since 0.2.0
```

Against an unmodified `v0.1.0` checkout all five fail. Any that *pass* on your
fork mean you have already addressed that finding some other way — adapt those
rather than overwriting.

## What is in this release

infrastructure that found them.

Each commit is independently green, so a subset can be applied in isolation
and `git bisect` is meaningful upstream.

If your fork is an unrelated-history import — no common ancestor with upstream
— cherry-picking by SHA will not work. Applying the diffs will. See
[Applying upstream patches](../DOWNSTREAM.md#applying-upstream-patches) for a
recipe validated against exactly that shape, including the two traps: pathspec
splitting for a relocated package root, and `git apply`'s all-or-nothing
behavior when a referenced file does not exist downstream yet.

## Suggested order

1. **Test infrastructure first** (`8035def`), re-derived for your build system
   — not ported. What must carry across in some form: `asyncio_mode = "auto"`
   (or an equivalent, otherwise every async test silently no-ops or errors)
   and registration of the `e2e` marker.
2. **The four fixes** (`4a7bd68`, `201d11c`, `af5ab52`, `3d6bbf9`). They touch
   three different modules and do not depend on each other.
3. **The E2E suites** (`265d7f1`, `bc54230`) last — they are the least likely
   to apply unchanged, and nothing else depends on them.

If you defer the E2E suites, note that `201d11c` also edits
`tests/test_e2e_protocol.py` (it removes an xfail the fix makes obsolete).
Exclude that path when applying, or `git apply` will discard the whole patch
including its `test_filter.py` changes — silently, with only a "No such file
or directory" line to signal it.

## Traps

Three things cost time here. They will cost it again if rediscovered.

**`os.path.normpath` does not fix `//etc/shadow`.** POSIX mandates preserving
exactly *two* leading slashes, so `normpath('//etc/shadow')` is a no-op —
while `normpath('///etc/shadow')` does collapse. The leading run must be
collapsed explicitly before normalizing. A fix that reaches for `normpath`
alone will pass a casual review and still be bypassable.

**The MCP in-memory session cannot be a pytest yield fixture.** pytest-asyncio
tears async generator fixtures down in a different task than it enters them,
and anyio then raises `RuntimeError: Attempted to exit cancel scope in a
different task`. Enter it with an `@asynccontextmanager` inside each test
instead. See `mcp_session()` in `tests/test_e2e_protocol.py`.

**Draining must precede reaping when killing a capped pipeline.** asyncio only
completes `Process.wait()` once every pipe has disconnected. Killing the
stages and immediately awaiting them deadlocks, because nothing is consuming
the last stage's stdout. Kill first, then drain, then reap — the order in
`run_pipeline` is deliberate, and `_kill` is split into `_signal_kill` /
`_reap` specifically to allow it.

## Check your catalog

Three of the fixes are `[behavior-change]`. Things that worked before and may
now behave differently:

- **Denied paths.** Arguments that previously slipped past `path_rules.deny`
  by respelling — `//`, `/./`, `/../`, or `--flag=/path` — are now denied.
  This is the point, but a catalog that relied on a `--flag=/path` form
  against a denied prefix will start failing.
- **Argument-less invocations.** `uptime`, `free`, `dmesg`, and bare pipe
  stages like `| wc` now work. **If you worked around this** — writing
  `| wc -l` to avoid a bare `| wc`, adding an explicit allow pattern for the
  empty case, or patching `check_command` — review those workarounds. They are
  the most likely source of a merge conflict in this release.
- **Truncated pipelines.** Now return `status: "success"` with
  `truncated: true`, where they previously returned `status: "error"` or, more
  often, never returned. Any client code branching on the error status for
  this case needs updating.

## Verifying the port

```bash
python scripts/verify/conformance.py     # all five pass
pytest -q                                # or your equivalent
pytest -q -m "not e2e"                   # if sockets are unavailable in CI
```

If a test fails after porting, check the table above to see which finding it
pins before assuming a porting error — it may be a real defect in your fork
that upstream's version does not have.
